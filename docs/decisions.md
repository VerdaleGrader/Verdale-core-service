# Decision log (engineering)

Product decisions live on the Notion page "Grader - Rebuild". These are the engineering decisions taken while building Milestone 1.

| Date       | Decision                                                                                                                                                                                                                                                                                           | Why                                                                                                 |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 2026-10-11 | Contracts live in `Verdale-core-service/contracts/` (OpenAPI 3.0 + HMAC spec + test vectors). Frontend and Judge vendor a pinned copy with `contracts.lock.json` (version + SHA-256 per file) and generate code from it; each repo's CI checks the lock and that generated code is current (GRD-7) | Core owns both APIs; a pinned copy keeps the other repos building without a shared package registry |
| 2026-10-11 | Generated code: `openapi-typescript` types in Core, `openapi-typescript` + `openapi-fetch` client in Frontend, `oapi-codegen` types in Judge (GRD-7)                                                                                                                                               | Small, type-only generators; no runtime framework lock-in                                           |
| 2026-10-11 | Contract change policy: additive changes are minor and receivers ignore unknown fields; breaking changes need a major version and a stated deploy order (`contracts/CHANGELOG.md`)                                                                                                                 | Lets the three services deploy independently                                                        |
| 2026-10-11 | One HMAC scheme in both directions with separate keyrings (core-to-judge, judge-to-core), key ids for rotation, ±300 s window (GRD-7)                                                                                                                                                              | A leaked callback key cannot submit jobs; rotation without downtime                                 |
| 2026-10-11 | One error shape everywhere: `{status, error_code, message, request_id, details?}` (GRD-8)                                                                                                                                                                                                          | Same handling in Frontend for Core and in Core for Judge                                            |
| 2026-10-11 | Local development uses a Neon `dev` branch, not a local Postgres container (GRD-2)                                                                                                                                                                                                                 | Matches production behaviour (pooler, SSL, scale-to-zero); chosen by the project owner              |
| 2026-10-11 | Core uses Fastify + Prisma 7 with the `pg` adapter: pooled URL at runtime, direct URL for Prisma CLI (GRD-9)                                                                                                                                                                                       | Same stack as the Trailblazer backend; Neon's pooler cannot run migrations                          |
| 2026-10-11 | Judge uses gin, viper, zap and go-redis (open-source equivalents of the Amaze `gcl` libraries) with the same controllers/services/repositories layout                                                                                                                                              | Avoid depending on a company-private module                                                         |
| 2026-10-11 | Python syntax errors are CE: Judge runs `python3 -m py_compile` in the sandbox as Python's compile step (GRD-35)                                                                                                                                                                                   | Same experience as C/C++; never wastes a test run                                                   |
| 2026-10-11 | Toolchains pinned to Debian 12: gcc/g++ 12.2.0 with `-std=c17` / `-std=c++17 -O2 -static`, Python 3.11.2; Judge refuses to start on a mismatch (GRD-34/35)                                                                                                                                         | Reproducible verdicts across machines                                                               |
| 2026-10-11 | isolate v2.7, a fresh box for the compile step and for every test (GRD-33)                                                                                                                                                                                                                         | cgroup accounting (e.g. the OOM flag) leaks between runs of the same box                            |
| 2026-10-11 | Output that reaches the output limit is OLE even if the program then exits with an error (GRD-37)                                                                                                                                                                                                  | Python ignores SIGXFSZ, so the write error would otherwise look like RE                             |
| 2026-10-11 | Judge state (job state, queue, result outbox) is all in Redis with AOF; results go to the outbox before the job is acked (GRD-32/39)                                                                                                                                                               | Judge has no database; at-least-once delivery with no lost results                                  |
| 2026-10-11 | Local test-file storage for Judge development is a plain directory named by SHA-256; production uses R2 over the S3 API (GRD-36)                                                                                                                                                                   | MinIO community is archived; the storage interface keeps R2 swappable                               |
| 2026-10-11 | The guide for running all three repos together lives in this README (GRD-1/GRD-2)                                                                                                                                                                                                                  | Core is the hub the other two talk to                                                               |
