# Decision log (engineering)

Product decisions live on the Notion page "Grader - Rebuild". These are the engineering decisions taken while building Milestone 1.

| Date       | Decision                                                                                                                                                                                                                                                                                           | Why                                                                                                                                                   |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 2026-10-11 | Contracts live in `Verdale-core-service/contracts/` (OpenAPI 3.0 + HMAC spec + test vectors). Frontend and Judge vendor a pinned copy with `contracts.lock.json` (version + SHA-256 per file) and generate code from it; each repo's CI checks the lock and that generated code is current (GRD-7) | Core owns both APIs; a pinned copy keeps the other repos building without a shared package registry                                                   |
| 2026-10-11 | Generated code: `openapi-typescript` types in Core, `openapi-typescript` + `openapi-fetch` client in Frontend, `oapi-codegen` types in Judge (GRD-7)                                                                                                                                               | Small, type-only generators; no runtime framework lock-in                                                                                             |
| 2026-10-11 | Contract change policy: additive changes are minor and receivers ignore unknown fields; breaking changes need a major version and a stated deploy order (`contracts/CHANGELOG.md`)                                                                                                                 | Lets the three services deploy independently                                                                                                          |
| 2026-10-11 | One HMAC scheme in both directions with separate keyrings (core-to-judge, judge-to-core), key ids for rotation, ±300 s window (GRD-7)                                                                                                                                                              | A leaked callback key cannot submit jobs; rotation without downtime                                                                                   |
| 2026-10-11 | One error shape everywhere: `{status, error_code, message, request_id, details?}` (GRD-8)                                                                                                                                                                                                          | Same handling in Frontend for Core and in Core for Judge                                                                                              |
| 2026-10-11 | Local development uses a Neon `dev` branch, not a local Postgres container (GRD-2)                                                                                                                                                                                                                 | Matches production behaviour (pooler, SSL, scale-to-zero); chosen by the project owner                                                                |
| 2026-10-11 | Core uses Fastify + Prisma 7 with the `pg` adapter: pooled URL at runtime, direct URL for Prisma CLI (GRD-9)                                                                                                                                                                                       | Same stack as the Trailblazer backend; Neon's pooler cannot run migrations                                                                            |
| 2026-10-11 | Judge uses gin, viper, zap and go-redis (open-source equivalents of the Amaze `gcl` libraries) with the same controllers/services/repositories layout                                                                                                                                              | Avoid depending on a company-private module                                                                                                           |
| 2026-10-11 | Python syntax errors are CE: Judge runs `python3 -m py_compile` in the sandbox as Python's compile step (GRD-35)                                                                                                                                                                                   | Same experience as C/C++; never wastes a test run                                                                                                     |
| 2026-10-11 | Toolchains pinned to Debian 12: gcc/g++ 12.2.0 with `-std=c17` / `-std=c++17 -O2 -static`, Python 3.11.2; Judge refuses to start on a mismatch (GRD-34/35)                                                                                                                                         | Reproducible verdicts across machines                                                                                                                 |
| 2026-10-11 | isolate v2.7, a fresh box for the compile step and for every test (GRD-33)                                                                                                                                                                                                                         | cgroup accounting (e.g. the OOM flag) leaks between runs of the same box                                                                              |
| 2026-10-11 | Output that reaches the output limit is OLE even if the program then exits with an error (GRD-37)                                                                                                                                                                                                  | Python ignores SIGXFSZ, so the write error would otherwise look like RE                                                                               |
| 2026-10-11 | Judge state (job state, queue, result outbox) is all in Redis with AOF; results go to the outbox before the job is acked (GRD-32/39)                                                                                                                                                               | Judge has no database; at-least-once delivery with no lost results                                                                                    |
| 2026-10-11 | Local test-file storage for Judge development is a plain directory named by SHA-256; production uses R2 over the S3 API (GRD-36)                                                                                                                                                                   | MinIO community is archived; the storage interface keeps R2 swappable                                                                                 |
| 2026-10-11 | The guide for running all three repos together lives in this README (GRD-1/GRD-2)                                                                                                                                                                                                                  | Core is the hub the other two talk to                                                                                                                 |
| 2026-10-11 | Sign-in is OAuth only (GitHub, Google), implemented in Core: authorization code + PKCE, server-side sessions (token hash in Postgres), no passwords (GRD-10). Revisit Better Auth if we add e-mail/password, MFA or many providers                                                                 | Smallest surface for the MVP; Core must create user + personal Space + session in one transaction and own the users table. Comparison in docs/auth.md |
| 2026-10-11 | Visitors who are not logged in can view public Spaces and published problems; submitting code requires login (GRD-15)                                                                                                                                                                              | Lets people see problems before signing up; limits abuse of the Judge to known accounts                                                               |
| 2026-10-11 | Only a verified provider e-mail may sign in or link accounts; the same verified e-mail through another provider is the same user (GRD-11)                                                                                                                                                          | Linking by an unverified e-mail allows account takeover                                                                                               |
| 2026-10-11 | usernames and Space slugs share one namespace; a personal Space's slug is its owner's username and follows renames in one transaction (GRD-12/16)                                                                                                                                                  | `/<slug>` URLs can never collide                                                                                                                      |
| 2026-10-11 | A private Space answers 404 to non-members, not 403 (GRD-15/17)                                                                                                                                                                                                                                    | Its existence is not leaked                                                                                                                           |
| 2026-10-11 | "Owner" is a membership role (several allowed); `spaces.created_by_id` records the creator. The last-owner rule is enforced in services (row lock) and by a deferred constraint trigger (GRD-14/18)                                                                                                | No code path can leave a Space ownerless, even under concurrent requests                                                                              |
| 2026-10-11 | Invitations never grant owner; link invitations are single-use; the token is returned once and only its hash is stored (GRD-18)                                                                                                                                                                    | A leaked database cannot be used to join Spaces; promote after joining                                                                                |
| 2026-10-11 | An archived Space is read-only; its members may still leave; personal Spaces cannot be archived or deleted (GRD-16/17)                                                                                                                                                                             | Matches "problems stay but no more submissions" and keeps every user's home Space                                                                     |
| 2026-10-11 | API lives under `/api/v1` (the prefix the Frontend proxies); CSRF defence is SameSite=Lax plus an `Origin` check on state-changing requests with a session; rate limits are per process, in memory (M2)                                                                                            | Matches the Frontend rewrite; a single VM is enough for the MVP, move limits to Redis if Core is ever scaled out                                      |
| 2026-10-11 | Cookie plugin pinned to `@fastify/cookie` 10.0.1                                                                                                                                                                                                                                                   | 11.x loads an ESM-only dependency that Jest (CommonJS) cannot import; upgrade together with moving tests to ESM                                       |
| 2026-10-11 | A problem has versions; a published version never changes. Enforced in the service (409 `VERSION_PUBLISHED`) and by database triggers on versions, tests and solutions (GRD-21)                                                                                                                    | Submissions must keep meaning exactly what they meant when they were judged; the trigger makes the rule independent of service bugs                   |
| 2026-10-11 | `problems.current_version_id` points at the version solvers see; drafts are a separate row, at most one per problem (partial unique index) (GRD-21)                                                                                                                                                | M4 can add the next draft while the published one stays current, with no change to readers                                                            |
| 2026-10-11 | Test files are stored by the SHA-256 of their normalised content at `tests/<sha256>` (the key Judge reads); identical content is stored once and removing a test never deletes objects (GRD-23/24)                                                                                                 | Content addressing makes objects immutable and shareable; deleting could break another test that uses the same bytes                                  |
| 2026-10-11 | Uploads are multipart, so the server sees raw bytes; files must be UTF-8 text without control characters, are normalised (BOM, CRLF to LF, one final newline) and are refused with the file name and the reason (GRD-25)                                                                           | A browser decoding a binary file as text would hide the problem; one normal form means one hash for one test                                          |
| 2026-10-11 | Limits: time 100 ms to 10 s, memory 16 MB to 1 GB, 100 tests, 8 MiB per file, 128 MiB per problem, 64 KiB per sample, 10 samples, 64 KiB source, 5 reference solutions, 2 MiB pictures (GRD-22/24/27). The API sends them as `constraints`                                                         | Inside the Judge contract and the database CHECKs, small enough for an MVP; one source of truth for the web app                                       |
| 2026-10-11 | `@aws-sdk/client-s3` for R2 behind a `FileStorage` interface, with one retry/timeout wrapper for every provider (GRD-23)                                                                                                                                                                           | The provider can change without touching business logic; retries behave the same everywhere and are testable with a fake                              |
| 2026-10-11 | Statement pictures: png, jpeg, webp only, type read from the bytes, random names, public bucket; the web app shows only pictures from Verdale's own storage (GRD-27)                                                                                                                               | SVG and HTML can carry script; an external image URL would tell an author who reads a problem                                                         |
| 2026-10-11 | Only owners and editors can read hidden-test metadata, reference solutions and drafts; author endpoints check the permission before looking up the problem; a draft is 404 for solvers (GRD-26/47)                                                                                                 | Status codes must not tell a solver which drafts exist                                                                                                |
| 2026-10-11 | Owners and editors of a Space can read everyone's submissions in it; everyone else only their own; others get 404 (GRD-46)                                                                                                                                                                         | Authors need to see how people fail; existence of a submission is not leaked                                                                          |
| 2026-10-11 | A submission is stored (`queued`) before Judge is asked, handed over by a background loop with exponential backoff, and becomes an ISE after 30 minutes without Judge. The job id is stored before the request goes out (GRD-44)                                                                   | Judge being down must not lose a submission; a fast callback must find its row                                                                        |
| 2026-10-11 | The result callback is idempotent per job id: duplicate is 204, a different verdict for a finished job is 409, an unknown or replaced job is 404, a bad shape is 422; is_sample comes from Core's records and hidden previews are dropped (GRD-45)                                                 | Judge delivers at least once; a late or duplicated result must never overwrite a newer state or leak hidden data                                      |
| 2026-10-11 | ISE is never the submitter's fault; it can be re-queued (`rejudge`) under a new job id by the author or an owner or editor (GRD-45)                                                                                                                                                                | The contract says Core must re-judge and not count it                                                                                                 |
| 2026-10-11 | Live status is Server-Sent Events where every connection starts with the full current state; polling `GET /submissions/{id}` is the fallback (GRD-46)                                                                                                                                              | Reconnects need no bookkeeping; works through the Next.js proxy (checked end to end)                                                                  |
| 2026-10-11 | Submissions are limited to 10 a minute per user with the `createRateLimit` helper keyed by user id; re-checks share the budget (GRD-44)                                                                                                                                                            | The route-level hook of the plugin is skipped when a global limit already ran, and runs before the session is known                                   |
| 2026-10-11 | Publishing in M3 is provisional: statement, language, a test, a sample and a primary reference solution. The Judge verification run comes in M4 (GRD-50 to 52)                                                                                                                                     | Solving cannot be tried end to end without some way to publish; the real gate belongs to the next milestone                                           |
